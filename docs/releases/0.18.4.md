# GoodVibes TUI `0.18.4`

First full public GitHub release of the TUI after the platform extraction and canonical SDK cutover.

This release is not a small patch note. It is the first release document for the current product shape: a terminal application built on top of the extracted `@pellux/goodvibes-sdk` platform layer, with compiled binaries, npm install support, and a working GitHub release/CD path.

## Release Scope

`0.18.4` captures the current GoodVibes TUI product surface, including the work that landed across the `0.18.0` through `0.18.4` line:

- provider routing and descriptive error hardening
- telemetry and control-plane contract expansion
- conversation follow-ups and panel workspace improvements
- global shortcut recovery and input/panel focus fixes
- daemon, transport, contract, and runtime seam extraction
- canonical SDK cutover from the temporary beta package to `@pellux/goodvibes-sdk`
- first real compiled-binary GitHub release flow for the TUI

## Product Surface In This Release

### Terminal Host

The TUI remains the product host and terminal experience:

- prompt/input flow
- conversation transcript rendering
- panel workspace and panel navigation
- shell-specific UX, overlays, and widget surfaces
- compiled application packaging and install path

### Platform Runtime

The release includes the full platform/runtime behavior exposed through the TUI host:

- in-process daemon and control-plane hosting
- operator and peer API surfaces
- remote runtime and event streaming
- provider routing and model selection
- automation, workflows, and WRFC loops
- knowledge ingest, memory, artifacts, and multimodal support
- channels, sessions, integrations, media, and telemetry surfaces

### SDK Foundation

The TUI now consumes the extracted canonical SDK instead of carrying duplicate local copies of the shared platform layer:

- canonical dependency: `@pellux/goodvibes-sdk@0.18.14`
- canonical contracts, transports, runtime helpers, and route surfaces
- canonical runtime inspection/state-inspector surface
- removal of duplicated local platform code that had already been extracted into the SDK

## Major Changes In This Release Line

### Canonical SDK Cutover

- Switched the TUI from the temporary beta SDK line to the canonical `@pellux/goodvibes-sdk` package.
- Rewired imports onto canonical SDK entrypoints.
- Removed large duplicated local platform segments after extraction, including shared contracts, daemon route handlers, runtime transports, state/runtime helpers, tooling helpers, utilities, and related platform modules.
- Moved the remaining state-inspector path onto the SDK-owned runtime inspection surface.

### Runtime, Transport, And Contract Hardening

- Added source-owned foundation contract types and generated typed operator, peer, and runtime-event client maps.
- Split the transport layer into explicit HTTP auth/retry/json, SSE/reconnect, direct-client, contract-route, operator remote-client, peer remote-client, and runtime/domain-event modules.
- Expanded runtime event metadata and distributed runtime contracts so remote clients and future companion surfaces can subscribe to named domains with stable payload semantics.
- Fixed extracted HTTP JSON transport behavior so explicit `Authorization` and `Content-Type` headers are preserved correctly.
- Hardened daemon contract and gateway catalog serialization around recursive schema responses.

### Provider Routing, Errors, And Telemetry

- Fixed explicit-provider routing so reviewer and fixer flows remain pinned to the selected provider instead of drifting to another provider exposing the same model id.
- Preserved upstream request ids, provider codes, and routing context across provider-boundary failures.
- Reworked the shared error model so provider, daemon, transport, and automation failures preserve structured categories, retry hints, request ids, and guidance.
- Added a first-class telemetry API with snapshots, events, errors, traces, metrics, SSE streaming, and OTLP-shaped export documents.
- Added control-plane auth and current-principal inspection endpoints so remote consumers can reason about auth state through the same contract surface as product APIs.

### Conversation, Panels, And Input UX

- Added lightweight assistant follow-up acknowledgements in the main conversation for agent completion/failure, cohort completion, and WRFC pass/fail milestones.
- Reworked the panel workspace around retained preloaded panels, a workspace tab strip, clearer system-message presentation, and startup prewarming.
- Restored the intended panel navigation model:
  - `Tab` swaps focus between prompt and panel area
  - `Ctrl+P`, `Ctrl+[`, and `Ctrl+]` remain global workspace controls
- Fixed extended-keyboard decoding so punctuation-based global shortcuts continue to work with panel focus active.
- Fixed global `Ctrl+C` so prompt clearing, cancel behavior, and exit-notice handling work consistently from input, panel, and modal focus states.
- Fixed tool-call and tool-result rendering so human-readable tool names are preserved and displayed correctly instead of falling back to opaque call ids or broken truncation.

### Release And Distribution Path

- Added a real tag-driven GitHub release workflow that re-runs validation before building binaries.
- Fixed release builds so all supported binaries are produced portably on `ubuntu-latest`, avoiding the earlier macOS-runner cancellation problem.
- Fixed manual reruns against an existing `v*` tag so they still execute the full release path instead of stopping at validation.
- Added an npm install smoke path for the TUI package distribution.
- Kept GitHub Releases as the primary binary distribution channel while preserving npm as an installable distribution path.
