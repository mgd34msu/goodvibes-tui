# GoodVibes TUI `0.18.4`

First public GitHub release of GoodVibes TUI.

GoodVibes TUI is the terminal application for the GoodVibes platform. It gives you a conversational shell, a panel workspace, a local daemon/control-plane host, provider routing, automation and workflow execution, remote runtime connectivity, knowledge and artifact handling, and releaseable binaries for Linux and macOS.

This document is the release note for that first public release.

## What GoodVibes TUI Includes

### Terminal application

- interactive prompt and conversation transcript
- panel workspace for secondary runtime and system information
- keyboard-driven shell UX
- compiled application binaries for Linux and macOS

### Platform runtime

- in-process daemon and control-plane host
- operator and peer APIs
- runtime event streaming
- workflow and automation execution
- WRFC loops
- provider routing and model selection
- channels, sessions, integrations, media, and telemetry support
- knowledge ingest, memory, artifacts, and multimodal support

### Shared platform foundation

The TUI now uses the extracted canonical SDK package instead of carrying duplicate local copies of the reusable platform layer:

- canonical dependency: `@pellux/goodvibes-sdk@0.18.14`
- canonical contracts, route handlers, transports, runtime helpers, inspection helpers, and related platform internals

## What Changed For This Release

### First public release packaging and delivery

- Added a real GitHub release flow for the TUI instead of leaving the product as source-only work.
- Published the npm distribution under the Pellux scope as `@pellux/goodvibes-tui` while keeping the installed CLI command as `goodvibes`.
- Built compiled release binaries for:
  - Linux x64
  - Linux arm64
  - macOS x64
  - macOS arm64
- Added release checksums with `SHA256SUMS.txt`.
- Added npm package install verification so the packaged distribution can be validated in a clean install flow.

### Canonical SDK cutover

- Switched the TUI from the temporary beta SDK line to the canonical `@pellux/goodvibes-sdk` package.
- Rewired imports onto the canonical SDK entrypoints.
- Removed duplicated local platform implementation that had already been extracted into the SDK, including shared contracts, daemon route handlers, transports, runtime helpers, utilities, and inspection logic.
- Moved the remaining local state-inspector path onto the SDK-owned runtime inspection implementation.

### Platform and runtime hardening

- Added typed operator, peer, and runtime-event contract surfaces.
- Hardened daemon contracts and recursive schema serialization.
- Split runtime transport concerns into clearer HTTP, SSE, reconnect, direct-client, remote-client, and domain-event paths.
- Preserved explicit auth and content-type header behavior in the extracted JSON transport.
- Improved provider routing so explicit provider choices stay pinned correctly.
- Improved structured error behavior so provider, daemon, transport, and automation failures carry richer context.
- Added stronger telemetry and control-plane auth/introspection surfaces.

### TUI interaction improvements

- Added lightweight assistant acknowledgements in the main conversation for agent completion/failure, cohort completion, and WRFC pass/fail milestones.
- Reworked the panel workspace around retained preloaded panels, clearer presentation, and better navigation behavior.
- Restored the intended focus/navigation model:
  - `Tab` swaps focus between prompt and panel area
  - `Ctrl+P`, `Ctrl+[`, and `Ctrl+]` remain workspace controls
- Fixed global shortcut handling, including `Ctrl+C`, punctuation-based control bindings, and panel-focus routing.
- Fixed tool-call and tool-result rendering so readable tool names are shown correctly instead of falling back to broken truncation or opaque call ids.

### Release-path fixes

- Fixed the release workflow so all target binaries build portably on `ubuntu-latest`.
- Fixed manual reruns against an existing `v*` tag so they still execute the real release path instead of stopping after validation.
- Fixed the eval/perf/architecture release gates after the SDK cutover removed old local paths.
