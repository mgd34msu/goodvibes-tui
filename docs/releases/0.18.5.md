# GoodVibes TUI `0.18.5`

Superseded packaging attempt for GoodVibes TUI.

This package shape was not the successful public registry release. The bundled-binary tarball for `0.18.5` exceeded npmjs and GitHub Packages size limits, and the corrected public package model shipped in `0.18.6`.

`0.18.4` established the canonical SDK cutover and the first public TUI release line. `0.18.5` was the follow-up attempt to correct the shipped distribution itself before the oversized bundled-binary tarball forced the final correction into `0.18.6`.

## What This Release Fixes

### Correct package identity and distribution targets

- npmjs package: `@pellux/goodvibes-tui`
- GitHub Packages mirror: `@mgd34msu/goodvibes-tui`
- installed commands:
  - `goodvibes`
  - `goodvibes-daemon`

This release keeps the user-facing command names stable while putting the package on the scoped registry identities that match the Pellux distribution model and the GitHub owner namespace.

### Bundled binaries instead of install-time downloads

The published npm package now contains the compiled binaries directly.

Bundled TUI binaries:

- Linux x64
- Linux arm64
- macOS x64
- macOS arm64

Bundled standalone daemon binaries:

- Linux x64
- Linux arm64
- macOS x64
- macOS arm64

This means npm installs no longer depend on downloading release artifacts during `postinstall`. The package already contains the runnable binaries under `vendor/`, and the launcher bins use those packaged artifacts directly.

### Global CLI surface

Global installs now expose both commands on the user path through the package `bin` surface:

- `goodvibes` for the interactive TUI
- `goodvibes-daemon` for the standalone daemon host

That keeps the npm-installed behavior aligned with the release artifacts and the source-run entrypoints.

## Release Automation Changes

### GitHub release path

The release workflow now:

- rebuilds the TUI and daemon binaries for all supported targets
- stages the vendored binaries before packaging
- validates clean install behavior against the packed npm tarball
- publishes to npmjs
- publishes to GitHub Packages
- creates the GitHub Release from this document

### Package validation hardening

The publish path now validates:

- both launcher bins exist and are executable
- vendored TUI binaries are present
- vendored daemon binaries are present
- checksums are present
- the packaged tarball excludes test-only and CI-only paths
- the staged publish package can be packed for both npmjs and GitHub Packages
