# GoodVibes TUI `0.18.9`

`0.18.9` is the TUI release that locks the product onto `@pellux/goodvibes-sdk@0.18.24` and cleans up the remaining host-boundary mistakes from the earlier cutover.

This release is about one thing: the TUI now uses the SDK-owned runtime surfaces while still keeping TUI-owned configuration, storage, and lifecycle decisions in the TUI host where they belong.

## What Changed

### Canonical SDK runtime updated to `0.18.24`

The TUI now depends on:

- `@pellux/goodvibes-sdk@0.18.24`

This release does not point at local SDK project files. It consumes the published package and updates the host-side wiring to match the SDK boundary that actually shipped.

### TUI-owned configuration is now passed explicitly into SDK services

The SDK defines the reusable runtime surface. The TUI decides how the TUI product configures that surface.

This release tightens that contract in the places that were still loose:

- ecosystem catalog and receipt roots are passed explicitly as TUI-owned paths under `.goodvibes/tui/ecosystem/...`
- daemon service management is created with `surfaceRoot: 'tui'`
- automation runtime setup uses `defaultSurfaceKind: 'tui'`
- local auth management is injected by the TUI host instead of being created implicitly inside shared SDK service bootstrapping

The result is that the TUI continues to own product-specific storage and runtime policy, while the implementation logic itself lives behind the SDK surface.

### Dead local ecosystem implementation removed

The TUI still had a stale local ecosystem catalog implementation in:

- `src/runtime/ecosystem/catalog.ts`

That local module is removed in `0.18.9`.

The live TUI surfaces already use the SDK package for:

- curated marketplace commands
- curated skills commands
- curated integration commands
- product/runtime summaries
- marketplace recommendations
- marketplace panel rendering

So this release finishes that boundary instead of leaving a second unused implementation in the TUI tree.

### Marketplace and artifact gates are corrected on the real host boundary

Two release blockers were closed in this pass:

- the marketplace panel test was still constructing SDK ecosystem paths without the TUI-owned catalog roots
- the foundation artifact gate was stale after the SDK `0.18.24` contract/runtime changes

This release fixes both:

- panel/runtime tests now use the real TUI host path contract
- checked-in foundation artifacts are regenerated from the canonical builders before release

## Summary

`0.18.9` is the TUI release where the SDK `0.18.24` cutover becomes operationally correct:

- published SDK package in use
- TUI-owned storage/configuration passed explicitly from the host
- dead local ecosystem duplication removed
- foundation artifacts refreshed
- full suite and release gates green again
