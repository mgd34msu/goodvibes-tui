# 0.18.20 — Wave 3a / Tier 2 TUI UX Consistency Infrastructure

**Released**: 2026-04-16
**Type**: Feature (infrastructure)

## Summary

Six infrastructure items that eliminate inconsistency in how panels handle destructive actions, errors, async loading, and escape focus. Every item is implemented at the base-class or shared-helper level so it applies uniformly to existing and future panels.

## What changed

### I1 — Reusable inline confirm dialog (`src/panels/confirm-state.ts`)

Extracted the `confirm: { sessionName } | null` y/n pattern from `session-browser-panel.ts` into a reusable composable helper. Three exports:

- `ConfirmState<T>` — generic interface `{ subject: T; label: string }`
- `handleConfirmInput<T>(confirm, key)` — returns `'confirmed'|'cancelled'|'absorbed'|'inactive'`
- `renderConfirmLines<T>(width, state)` — returns 2-line y/n dialog `Line[]`

Applied to:

- **SkillsPanel** `d` key: shows `Confirmation` section; confirmed path surfaces `rm "<path>"` shell hint via I2
- **KnowledgePanel** `s`/`c` keys: prompts before calling `registry.review()` with stale/contradicted state
- **SubscriptionPanel** logout: `n`/Esc now cancels via confirm helper instead of ad-hoc branch

### I2 — Error surface slot on BasePanel

Added to `src/panels/base-panel.ts`:

```typescript
protected lastError: string | null = null;
protected setError(msg: string): void
protected clearError(): void
protected renderErrorLine(width: number): Line | null
```

`renderErrorLine` returns bold red (`#ef4444`) text with `✕ ` glyph prefix, or null when no error is set.

`ScrollableListPanel.handleInput()` auto-clears the error on the first keypress after it's set.

`ScrollableListPanel.renderList()` computes an `effectiveFooter` array: the error line is prepended to the caller's footer so it appears above keyboard hints. Both empty-state and normal-state render paths use `effectiveFooter`.

Applied to:
- **MarketplacePanel**: `refresh()` wraps `loadEcosystemCatalog` calls in try/catch and pipes failures through `setError()`
- **KnowledgePanel**: `registry.review()` in the confirm dispatch is wrapped in try/catch

### I3 — Loading spinner slot on BasePanel

Added to `src/panels/base-panel.ts`:

```typescript
protected loadingState: 'idle' | 'loading' | 'error' = 'idle';
protected startLoading(label?: string): void
protected stopLoading(): void
protected renderLoadingLine(width: number, frame?: number): Line | null
```

Uses `SPINNER_FRAMES` (braille spinner) from `src/renderer/progress.ts`. The spinner line is rendered in purple-ish `135` ANSI color for visibility.

`ScrollableListPanel.renderList()` short-circuits to a header + spinner view when `loadingState === 'loading'` — no stale list items appear during async fetches.

Applied to:
- **GitPanel** `openDiff()`: calls `startLoading('Loading diff...')` before the diff await; `stopLoading()` in both success and error branches. `render()` routes `loadingState === 'loading'` to the existing `renderMessage()` helper.

### I4 — Accessible status tokens (`src/renderer/status-token.ts`)

New file exports:

```typescript
export type StatusState = 'good' | 'warn' | 'bad' | 'info';
export function buildStatusToken(state, label, opts?): Cell[]
```

Glyph map: `good=✓`, `warn=⚠`, `bad=✕`, `info=○`. Glyph and color both applied as redundant cues so colorblind users can parse state without relying on color alone.

Applied to **ApprovalPanel** lines 84–87: the approval/denial/pending row now uses inline `✓ approvals (N)  ✕ denials (N)  ○ pending (N)` segments instead of bare color-only count values.

### I6 — Two-stage Escape in panel focus (`src/input/handler-feed-routes.ts`)

Previous behavior: Escape while panel-focused unconditionally cleared `panelFocused`, so panels never received the key.

New behavior: `handlePanelFocusToken()` now passes `'escape'` to `activePanel.handleInput('escape')` first. If the panel returns `true` (consumed — e.g. dismisses a confirm dialog or clears a search query), focus stays on the panel. If the panel returns `false`, `panelFocused` is set to false as before.

This enables the confirm dialogs added in I1 to be dismissed cleanly with Escape without also blurring the panel.
