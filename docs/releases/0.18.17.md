# 0.18.17: Companion pairing, QR alignment, SDK 0.18.37 bump

**Released**: 2026-04-16
**Type**: Patch (bug fixes + dependency bump)

## Summary

Two user-facing bugs closed plus a follow-on SDK bump:

1. **QR pairing was broken end to end.** The `/qrcode` panel advertised a companion bearer token, but the embedded daemon was never told to accept it. Every phone scan resulted in `authenticated: false, authMode: "invalid"` from `/api/control-plane/auth`.
2. **QR was visually mis-aligned.** One extra column of white on the left and no top quiet band made the finder patterns look off-square; mobile QR readers still decoded it but humans reviewing the panel saw an offset grid.

## What changed

### TUI

- `src/runtime/bootstrap.ts`: the deferred `external-services` startup task now loads `getOrCreateCompanionToken('tui')` and passes it as `sharedDaemonToken` to `startExternalServices`. The embedded daemon registers the same token the QR panel advertises, so scanned bearer credentials authenticate.
- `src/renderer/qr-renderer.ts`: `leftPad` reduced from 2 to 1, and a one-row top quiet band is prepended before the half-block matrix rows. Finder-pattern quiet margins are now 1 cell on both axes (visually equal).
- `src/test/runtime/bootstrap-services.test.ts`: enable expectations updated to match the new `enable(config, token?)` signature.
- `docs/foundation-artifacts/*`: regenerated against SDK 0.18.37.
- `package.json`: version 0.18.16 → 0.18.17; SDK dep 0.18.36 → 0.18.37.

### SDK changes picked up (0.18.37)

- `startHostServices` accepts `sharedDaemonToken` and `sharedHttpListenerToken` in its factories, threading them to `daemon.enable(...)` / `httpListener.enable(...)`.
- `UserAuthManager` constructor detects drift between `auth-bootstrap.txt` and `auth-users.json` and logs a WARN. Manual edits to the bootstrap file no longer silently break `/login`.

## One-time user data repair

Builds deployed prior to this release may have an `auth-bootstrap.txt` that does not verify against `auth-users.json`. To re-sync:

```bash
bun -e 'import { UserAuthManager } from "@pellux/goodvibes-sdk/platform/security/user-auth"; \
  const mgr = new UserAuthManager({ \
    bootstrapFilePath: "$HOME/.goodvibes/tui/auth-users.json", \
    bootstrapCredentialPath: "$HOME/.goodvibes/tui/auth-bootstrap.txt" \
  }); \
  mgr.rotatePassword("admin", "your-new-password");'
```

Or delete both files to force a fresh bootstrap on next TUI start.

## Verification

- `bun run test`: 437 test files, all pass
- `bunx tsc --noEmit`: clean

- Phone scan of the `/qrcode` panel QR authenticates against the embedded daemon (no more 401 on `/api/control-plane/auth`)
