# 0.18.13

`0.18.13` is the SDK/TUI boundary separation release. The TUI is now a thin rendering, input, and wiring layer built on `@pellux/goodvibes-sdk@0.18.29`. Thousands of lines of duplicated, forked, and dead code have been removed and replaced with SDK imports.

## Why This Release Matters

The goodvibes-tui and goodvibes-sdk were split from a single codebase, but the split was incomplete. The TUI still contained full copies of SDK classes (Orchestrator, ConversationManager, plugin loader, tool registration, runtime services), dead code from abandoned local daemon files, and duplicate store domain/reducer implementations. This release completes the separation.

The principle: **the SDK is the platform, the TUI is one surface built on it.** The SDK provides orchestration, tools, providers, config, sessions, channels, automation, knowledge, daemon, and infrastructure. The TUI provides terminal rendering, keyboard input, panels, and the wiring that connects SDK services to the terminal.

## What Changed

### Dead Code Removed (~1,600 lines)

Four daemon files (`facade.ts`, `facade-composition.ts`, `surface-policy.ts`, `types.ts`) were stale forks of SDK code that nothing in the TUI imported. The TUI's `cli.ts` already imported `DaemonServer` from the SDK. Two UI read-model files were dead code superseded by the SDK's implementations.

### Forks Replaced with SDK Imports (~2,200 lines)

Seven files that were near-identical copies of SDK code were replaced with thin re-exports:

- **Orchestrator** (736 → 3 lines): The SDK's Orchestrator already had every method the TUI used, including `getSpinner()`. No subclass needed.
- **Plugin loader** (305 → re-exports): The SDK now accepts `additionalDirectories` and `entryDefault` options, so the TUI no longer needs to fork the loader to add `.goodvibes/tui/plugins`.
- **Tool registration** (187 → re-export): The SDK's `registerAllTools` takes `surfaceRoot` as a parameter.
- **Subscription providers** (128 → re-export): Identical OAuth configs.
- **API key resolution** (123 lines removed): The SDK now has `config/api-keys.ts` with the canonical 30+ provider-to-env-var mapping.
- **Permission types** (4 type definitions removed): Imported from SDK instead of redefined.
- **Store domains + reducers** (4 files → re-exports): Conversation domain, permissions domain, and both reducer files were byte-for-byte identical.

### ConversationManager Refactored (776 → ~450 lines)

The TUI's `ConversationManager` was a standalone class that duplicated all of the SDK's message management (CRUD, branching, persistence, compaction, undo/redo) plus added ~430 lines of terminal rendering. It now extends the SDK's `ConversationManager`, inheriting all message management and keeping only the rendering layer:

- `TuiBlockMeta extends BlockMeta` adds rendering fields (`blockIndex`, `startLine`, `lineCount`, `collapseKey`)
- All message methods are inherited from the SDK base class
- Override methods call `super.method()` first, then mark display dirty

### Health Monitoring Renamed (20 files)

The SDK generalized `PanelHealthMonitor` to `ComponentHealthMonitor` (since health monitoring is infrastructure, not a TUI concept). The TUI was updated to match: `panelHealthMonitor` → `componentHealthMonitor` throughout runtime, panels, diagnostics, bootstrap, and tests. Deprecated `Panel*` aliases remain for backward compatibility.

### RuntimeState Aligned with SDK

The SDK's `RuntimeState.panels` changed from `PanelDomainState` to `Record<string, unknown>` (surfaces define their own panel shape), and `uiPerf` became `surfacePerf: SurfacePerfDomainState`. The TUI's store was updated to match while preserving its typed `PanelDomainState` through casts.

### Clipboard Split

The SDK's `clipboard.ts` contained both terminal-specific code (OSC 52 copy) and platform-level code (system clipboard paste). The terminal copy was moved to the TUI; the platform paste functions remain in the SDK.
