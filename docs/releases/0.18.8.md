# GoodVibes TUI `0.18.8`

`0.18.8` is the real public TUI release that finishes the canonical SDK cutover work and clears the release-path failures that blocked the later `0.18.x` attempts after `0.18.4`.

This release does two things at the same time:

- it finishes moving the remaining shared REPL and sandbox runtime logic onto the published `@pellux/goodvibes-sdk` package
- it hardens the TUI-owned host configuration and release validation path so the cutover actually ships cleanly

## What Changed

### Canonical SDK package is now the real runtime dependency

The TUI now consumes the canonical published SDK line:

- `@pellux/goodvibes-sdk@0.18.21`

This is no longer the temporary beta path and it is no longer a mix of SDK plus leftover local copies for the REPL and sandbox runtime cluster.

Concretely, this release removes the remaining local TUI copies of:

- the REPL tool runtime
- sandbox backend wiring
- sandbox manager/provisioning/session registry logic

Those flows now resolve through the SDK package surface instead of local TUI implementations.

### TUI-owned configuration stays TUI-owned

The cutover also tightened the boundary that matters for the product:

- the SDK defines the reusable runtime surface
- the TUI defines how the TUI product configures and stores its own state

This release fixes the places where that boundary was still loose by making the TUI pass explicit host configuration into SDK-owned services.

Examples:

- cross-session task graphs are wired to `.goodvibes/tui/sessions/task-graph.json`
- team and worklist tools are created with `surfaceRoot: 'tui'`
- TUI-owned secret-store and language-override tests are now aligned with the actual host-owned storage paths

The important result is that the SDK is no longer deciding where the TUI stores product state. The TUI host does that explicitly.

### Release-path temp-root failures are closed

The public release path was still vulnerable to temp-filesystem quota failures. This release closes that gap across the suite instead of just in the REPL tests.

Changes in this pass:

- `scripts/run-tests.ts` now gives each test file its own repo-local temp root under `.test-tmp/suite/...`
- tests that were still hardcoding `/tmp` or depending on shared temp roots were moved onto the active temp root
- tests that intentionally validate path escape behavior now use explicit external directories instead of relying on `/tmp`

That means the release path no longer depends on shared system temp space staying healthy across the full suite.

### Intelligence test runtime is now cycle-safe

The SDK cutover exposed a module-initialization cycle in the TUI test helper for intelligence services.

This release fixes that by lazily initializing the helper-owned runtime roots and service singletons instead of eagerly building them at module load time. The result is:

- no temporal-dead-zone failures during test module evaluation
- no helper state created before the test runtime actually asks for it
- cleaner isolation between intelligence tests and the wider runtime-service graph

### Panel detail rendering keeps useful path context

The Skills panel used to clip long origin paths by keeping the prefix and dropping the useful file suffix.

This release changes the panel to use a path-aware truncated display that keeps the meaningful tail visible. That preserves the file the operator is actually inspecting instead of only showing the start of a long absolute path.

## Package Distribution

This release keeps the public package model established in the earlier packaging corrections:

- npmjs package: `@pellux/goodvibes-tui`
- GitHub Packages mirror: `@mgd34msu/goodvibes-tui`
- installed commands:
  - `goodvibes`
  - `goodvibes-daemon`

Published installs still use the staged release-asset model:

- `npm install -g @pellux/goodvibes-tui`
- install-time `postinstall` downloads the version-matched TUI and daemon binaries for the current platform
- source checkouts skip release-binary installation during `bun install`

Supported packaged install targets remain:

- Linux
- macOS
- WSL

Native Windows is still not a supported packaged runtime target.

## Summary

`0.18.8` is the release where the TUI side of the platform split becomes coherent again:

- canonical SDK package in use
- remaining REPL and sandbox runtime duplication removed from the TUI
- TUI-owned storage and host configuration made explicit
- full release validation no longer depends on fragile shared temp roots
- npm, GitHub Packages, GitHub Releases, and install smoke all have one consistent delivery path
