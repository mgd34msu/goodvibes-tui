# GoodVibes TUI 0.18.23

**Release date**: 2026-04-16
**Type**: Performance bundle (conversation-rendering + feed-context reuse) + review follow-ups + regression fixes

## Summary

Bundles the conversation-rendering double-parse elimination and the feed-context
object reuse performance commits into a single versioned release.
Also addresses all five follow-up items raised during review and fixes two
regressions uncovered during that review.

## Performance changes

### Conversation-rendering

`src/core/conversation-rendering.ts` previously called `renderMarkdown()` (the
untracked legacy renderer) a second time for `'code'` mode to obtain a line count
for the gutter width. This change removed the duplicate call; the line count is now
derived from the `renderMarkdownTracked()` call that was already made.

The `'all'` mode still makes two `renderMarkdownTracked()` calls: one measurement
pass at full width to determine `numWidth` (and thus `gutterW`), then a render pass
at `width - gutterW`. This double-call is unavoidable by design and is documented
with an inline comment. The `'all'` mode path was left unchanged.

### Feed-context object reuse

`InputHandler` previously constructed a new `InputFeedContext` object on every
`feedInputTokens()` call, allocating 14+ fields per keystroke. This change moves to
a single long-lived context object:

- `initFeedContext()` runs once at startup, wiring all stable service handles,
  closures, and callbacks into the context.
- `syncFeedContextMutableFields()` runs before each `feedInputTokens()` call,
  updating only the 14 mutable fields (`prompt`, `cursorPos`, `commandMode`, etc.).
- Eliminates per-keystroke allocation pressure on the hot input path.

## Regression fixes

### R1: handler.ts architecture cap (800-line limit)

`handler.ts` grew to 830 lines after the feed-context reuse change (the factory and sync functions added
more lines than they conceptually saved). Fixed by extracting the factory functions
into `src/input/feed-context-factory.ts`:

- `buildInitialFeedContext(mutable, stable, closures)`: assembles the long-lived
  `InputFeedContext` from three typed partial objects.
- `syncFeedContextMutableFields(fields, ctx)`: exported for documentation purposes;
  the inline version in `handler.ts` is the authoritative copy for the hot path.
- Interfaces `FeedContextMutableInit`, `FeedContextStableRefs`, `FeedContextClosures`
  provide structured typing for the three parameter groups.

`bun run architecture:check` passes with `handler.ts` at exactly 800 lines.

### R2: SearchableListPanel cursor glyph substitution

`buildFilterInputLine` (added in an earlier UX-consistency pass) rendered the
focused filter line as `[Filter] query_`, but the trailing `_` was being
substituted with the block cursor glyph `█` by `buildSearchInputLine` when
called with `active:true`.

Root cause: `buildSearchInputLine` in `src/panels/polish.ts` substitutes any
trailing `_` with `GLYPHS.surface.cursor` (█) when `active:true`. That pass's
spec states the cursor is a literal `_` character.

Fix: pass `active:false` with explicit `bg: palette.inputBg` and
`valueColor: palette.info` options. The focused visual affordance comes from the
`[Label] ` bracket format; the `active` flag is not needed. Fixes the one
pre-existing test failure carried over from 0.18.22.
