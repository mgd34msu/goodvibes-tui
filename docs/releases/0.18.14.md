# 0.18.14

`0.18.14` overhauls panel navigation, fixes modal viewport sizing, adds the settings tools tab with model picker integration, and introduces QR code pairing for mobile companion apps.

## What Changed

### Panel Navigation Is Now Consistent Everywhere

Previously, 46 panels each implemented their own scroll/cursor management with hand-coded `Math.max`/`Math.min` logic. Navigation key bindings varied between panels, scroll position could lose track of the selection, and there was no shared infrastructure.

This release introduces `ScrollableListPanel<T>` and `SearchableListPanel<T>` base classes that handle all navigation, scroll clamping, and viewport windowing. 30 panels have been migrated. Every migrated panel now supports:

- `up`/`down`/`j`/`k` — single item movement
- `pageup`/`pagedown` — page-at-a-time movement
- `home`/`end`/`g`/`G` — jump to first/last
- `enter` — select/activate

All navigation uses `getTrackedVisibleWindow()` from `surface-layout.ts` — one function, one behavior, everywhere. The selection is always visible within the viewport.

Panels that were migrated include: hooks, mcp, plugins, tasks, schedule, routes, skills, knowledge, memory, services, watchers, automation, control-plane, security, local-auth, provider-accounts, git, agent-logs, worktree, forensics, eval, approval, communication, orchestration, remote, marketplace, session-browser, and more.

### Modal Viewport Sizing Is Fixed

Modals are now a fixed, predictable size:

- **Height**: exactly 45% of viewport (both minimum and maximum — all modals are the same height)
- **Width**: 50% of viewport, with a 25% minimum floor
- **Margins**: preserved (4 columns on narrow terminals, 6 on wide)

Previously, modals had variable sizing with hardcoded width caps (72/78/84 columns) and height ratios that produced inconsistent results.

6 modal/overlay files were also updated to use the shared `getVisibleWindow()` function instead of inline scroll math: autocomplete overlay, file picker, bookmark modal, session picker, profile picker, and live tail modal.

### Settings Modal Now Has a Proper Tools Tab

The settings modal's tools tab previously rendered helper and tool LLM settings as generic string fields with no specialized UI. You couldn't actually set a helper or tool model.

This release adds:

- Section headers ("Tool LLM" / "Helper Model") for visual grouping
- Boolean settings (`helper.enabled`, `tools.llmEnabled`) display as `[on]`/`[off]` toggles
- Provider/model settings open the **full model picker** when activated (same UI as Ctrl+M)
- The model picker now supports 3 target modes: `main`, `helper`, and `tool`
- Selecting a model for helper/tool automatically enables the feature

### Tool LLM Defaults to Off

Previously, `tools.llmProvider` and `tools.llmModel` defaulted to empty strings, which caused `resolveToolLLM()` to silently fall back to the main conversation model — meaning tool LLM was effectively always on.

SDK 0.18.30 adds `tools.llmEnabled: false` as an explicit gate, matching the existing `helper.enabled: false` pattern. Tool LLM is now opt-in.

### QR Code Pairing for Mobile Companion Apps

New `/qrcode` command (aliases: `/qr`, `/pair`) opens a panel displaying a QR code that mobile companion apps can scan to connect to the daemon.

The QR code encodes:
- Daemon URL
- Permanent companion auth token (`gv_` prefixed)
- Username
- Version

The panel supports:
- `r` — regenerate token (invalidates the old one, generates new QR)
- `c` — copy token to clipboard

When running the daemon standalone (`goodvibes-daemon`), the QR code and connection info are printed to stdout automatically after boot.

Companion tokens persist to `.goodvibes/tui/companion-token.json` and survive restarts. Regeneration invalidates the previous token immediately.

The QR generator (in SDK 0.18.30) uses `qrencode` CLI when available, with a built-in fallback encoder for environments without it.

### Health Monitoring Rename

`panelHealthMonitor` renamed to `componentHealthMonitor` across 20 files to align with SDK 0.18.29's generic naming. Health monitoring is infrastructure — any surface needs it, not just the TUI. Deprecated `Panel*` type aliases are preserved for backward compatibility.
