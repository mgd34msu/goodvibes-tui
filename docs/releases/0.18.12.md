# 0.18.12

`0.18.12` closes the remaining TUI validation tail after the SDK cutover by moving the TUI onto the published `@pellux/goodvibes-sdk@0.18.28` package and fixing the last boundary and test-path regressions that were still blocking a clean release.

## What Changed

### TUI Moved To The Published SDK `0.18.28`

The TUI now consumes the published canonical SDK package at `@pellux/goodvibes-sdk@0.18.28`.

That SDK patch fixes one real host-boundary bug:

- session bodies were already written under the TUI-owned `surfaceRoot: 'tui'`
- but the shared last-session pointer and crash-recovery helpers were still resolving through the unscoped `.goodvibes/...` root

That was the wrong storage split for the TUI product.

`0.18.28` fixes the SDK side of that by threading `surfaceRoot` through:

- `getUserSessionsDir(...)`
- `getLastSessionPointerPath(...)`
- `getRecoveryFilePath(...)`
- the pointer write/read helpers
- the recovery write/read/check/delete helpers

With this TUI release, the session body, last-session pointer, and crash-recovery metadata all stay under the same TUI-owned surface tree again.

### Validation Tail Moved Off `os.tmpdir()`

The release-blocking failures left in the TUI were no longer product-runtime failures. They were validation-tail failures caused by test temp roots still being created under `os.tmpdir()`, which was hitting local quota limits.

This release moves the remaining affected test paths onto the repo-local `.test-tmp/...` root, including:

- session manager tests
- template manager tests
- session picker tests
- bootstrap-services tests
- plugin-system tests
- the shared runtime test helper path used by integration tests

That keeps the test harness aligned with the local filesystem constraints instead of depending on the host temp filesystem being writable and spacious.

### Cutover Gates Were Updated To Match The Live Tree

The TUI cutover and enforcement gates were also still carrying stale assumptions from before the SDK extraction completed.

This release fixes that by:

- updating the shell-control cutover gate to assert against the current TUI production surfaces and the intentional absence of removed local platform files
- removing the stale typed-emission allowlist entry for `src/runtime/health/effect-handlers.ts` after that file was deleted from the live tree

That means the release gates now validate the current architecture instead of an older pre-cutover layout.
