# GoodVibes TUI `0.18.10`

`0.18.10` is the TUI patch release that picks up `@pellux/goodvibes-sdk@0.18.25` and closes the compiled-binary startup crash that still remained after the earlier SDK cutover.

This release exists for one concrete reason: the TUI binary could still die on startup before a prompt was even shown because the shared SDK tool surface was pulling an AST native binding during module initialization.

## What Broke

The failure showed up on the real compiled startup path:

- `bun run build`
- `./dist/goodvibes`

The crash was not in TUI-only renderer or shell code. It came from the shared SDK tool layer:

- the TUI registers the full tool surface during startup
- the SDK structural-find and `ast_pattern` edit paths were still importing `@ast-grep/napi` at module top level
- that forced the native AST binding to resolve during host boot, even when the user had not asked for any AST-backed operation

That was the wrong boundary. Hosts should be able to boot and register tools without immediately needing the AST runtime.

## What Changed

### TUI moved to SDK `0.18.25`

This release updates the package dependency to:

- `@pellux/goodvibes-sdk@0.18.25`

The TUI is consuming the published package version, not a local SDK filesystem import.

### Startup crash removed at the real boundary

The actual fix lives in the SDK:

- `@ast-grep/napi` is now lazy-loaded only when an AST-backed feature is actually used
- startup-sensitive tool modules no longer import the native binding at module top level

That means the TUI does not need a product-local workaround. It can keep booting through the shared SDK surface and still start cleanly.

### Compiled binary path revalidated

This release explicitly revalidated the path that was broken:

- compile the TUI binary
- launch `./dist/goodvibes`
- confirm the app reaches a live running terminal session instead of throwing on native module resolution

That matters because the earlier failure only showed up on the real compiled binary path, not just from source-run development flows.

## Why This Release Matters

The previous TUI release had already completed the SDK cutover structurally, but a host-startup bug still existed in the shared package.

`0.18.10` is the release where that cutover becomes operationally correct for the compiled TUI binary:

- published SDK package in use
- no local TUI workaround layered on top
- shared startup path fixed where the bug actually lived
- compiled binary confirmed working again
